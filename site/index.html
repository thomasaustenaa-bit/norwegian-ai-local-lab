01 · System design

A small, clear path from prompt to answer.

Keep the model and private inputs on the PC. Make each part swappable so a modest machine can start small and grow with better hardware.

01 / INPUT

Local interface

A lightweight chat or task client sends a request to the machine.

02 / ROUTING

Model gateway

One local endpoint selects a model and applies request limits.

03 / INFERENCE

PC runtime

A replaceable inference engine serves a quantized model on CPU or GPU.

04 / EVIDENCE

Evaluation log

Latency, throughput, hardware, and model details become comparable records.

Local by default: no cloud API is needed for the reference path. Model downloads are a separate, explicit step; prompts and measurement records remain on the device unless the operator exports them.
02 · Design principles

Built to be checked, changed, and reused.

The project starts with a reproducible blueprint and a measurement harness. It does not assume one model, runtime, or PC is best for everyone.

01

Measure, then compare

Record the model, quantization, runtime, hardware, prompt set, and run conditions alongside every result.

02

Be honest about trade-offs

Quality, memory, speed, heat, and energy use all matter. Publish limits with the headline metric.

03

Make language coverage visible

Use Somali and English examples, and document where prompts or evaluation methods need fluent review.

03 · Hardware profiles

Start with the machine you have.

These are planning profiles, not measured recommendations. Exact model fit depends on context length, quantization, runtime, operating system, and available memory.

Profile A · Entry

Everyday PC

CPU-first or modest integrated graphics

Target: smaller quantized models
Measure: memory use and response delay
Profile B · Balanced

Creator desktop

More memory, optional consumer GPU

Target: mid-sized quantized models
Measure: CPU/GPU split and tokens/sec
Profile C · Workstation

Local lab

High-memory GPU or multi-device setup

Target: larger models and longer context
Measure: concurrency, power, and quality
Benchmark status: not measured yet
The repository includes a starter harness. Results will be published only after reproducible runs with hardware and model details.
